1. PDF generation & preview ● Live & verified

Every generated document showed “no PDF / not generated”, and the in-app preview was blank.

Root cause. DOCX→PDF conversion drives Microsoft Word through COM. The app ran as the LocalSystem Windows service account, and Word automation simply does not work there — it failed or hung, leaving 15 zombie Word processes piling up. Result: pdf_path was NULL for all 7 documents.
Fix. Created the Word “Session-0” desktop folders and reconfigured the GSSGManager service to run as the Admin user (real profile → Word behaves). Cleared the zombies. Confirmed working end-to-end — you generated a General Book and the PDF rendered.
Surfaced
0 / 7 documents had a PDF; preview showed the generic “couldn’t render”.
Also improved
The viewer now says “No PDF was generated — download the DOCX” instead of a vague error.
Recorded
Saved to project memory so a service reinstall doesn’t silently reset it.

4. Notifications overhaul ● Needs restart

Push notifications resent the same items repeatedly, only opened the app root, and were English-only. Rebuilt around a durable per-item ledger.

Only new items, once

A durable push_sent ledger tracks each item per user, so a still-open item is sent once and never replays on restart. The existing backlog was seeded as “already sent”.

Tap → the exact item

Each push carries a deep link; the service worker routes client-side (fixing the iOS blank-page) to the precise book / scan / inbox.

Sign vs review

Approvers get “awaiting your signature”, reviewers “awaiting your review”, with the document subject + who submitted it.

One device, one user

A shared phone registered under two accounts caused double messages — an endpoint now belongs to a single user (existing duplicate pruned).

Under the hood

  • Time-limited grants — user_permissions.expires_at; resolution ignores expired grants; a once-a-minute sweep revokes them.
