Implementation plan after UI approval

Clean cutover: one server-owned notifier capability, one two-state handoff surface, the existing approval dialog, and the existing printable record page.

01

Make notifier coverage server-owned

Expose a notifies_employee flag in template metadata from the same backend capability set used by auto-send—including leave, administrative leave, duty resumption, violation, and every mapped book event. Remove the duplicated frontend form list.

02

Build one two-state handoff bar

Before save: notifier-backed forms show the default-on per-record switch and Save to Records. After save: the same position shows Saved, the notification outcome, Print, Send for approval, and Open record.

03

Connect every save path

Generated forms pass notify_employee with the committed save and resolve the new book by reference. Word Finish already returns BookRead; Duty transfer already returns book_id and ref. Non-notifying services skip the switch.

04

Make Print consistent and reliable

Use the existing full-record print surface for every service. Open the record in print mode, wait for its PDF canvas to finish, then invoke the print dialog once.

05

Reuse the approval workflow

Open the current manager/reviewer dialog. No duplicate approval logic. On success, refresh Books/Dashboard and change the completion status to “Sent for approval.”

06

Remove the Report dead action

Show Save as template only when the finished version’s template_id is General Book. Reports keep the same Word finish and preview, without an action the backend rejects.

07

Verify real operator paths

Exercise notifier On and Off for every notifier-backed template family, plus General Book, Report, and Duty transfer in English/Arabic, desktop/phone, light/dark. Verify actual outbound-message logs, print output, and approval submission.
